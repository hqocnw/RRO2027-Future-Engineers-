RRO2027 Future Engineers

1. Что это
Визуальный симулятор автономного робота, который:

ездит по двухэтажному полю 8×8;

заезжает/съезжает по пандусам между этажами;

собирает трубы (красные и синие, на 1-м и 2-м этажах);

доставляет их на зелёные подставки.

Программа строит маршрут волновым алгоритмом (BFS), перебирает варианты порядка объезда труб, выбирает кратчайший по суммарной длине и проигрывает движение робота в окне OpenCV.

2. Установка и запуск
bash
pip install opencv-python numpy
python simulator.py
Требования: Python 3.8+, opencv-python, numpy.

Скрипт:

загружает карту map_draw и собирает поле из картинок img/;

ставит робота в robot_pos = [4,4];

calc_path() — перебирает 6 порядков объезда труб, считает длины, выбирает минимальную;

рисует найденный маршрут цветными точками;

по нажатию клавиши в окне pole проигрывает движение по 4 участкам fin_path.

Управление: любая клавиша — следующий этап/участок; Esc — выход.

4. Карта и коды клеток
map_draw — матрица 8×8, каждая ячейка — код типа клетки:

Код	Значение
1	пол 1-го этажа
2	пол 2-го этажа
61–64	пандусы (переходы между этажами)
151, 152	красные трубы на 1-м этаже
251, 252	красные трубы на 2-м этаже
121, 122	синие трубы на 1-м этаже
221, 222	синие трубы на 2-м этаже
31–34	зелёные подставки (места выгрузки)
Проходимость клеток задают словари:

dict_p — какие клетки достижимы из данной (для волнового алгоритма и поиска пути);

dict_tube — из какой клетки можно «подъехать» к трубе/подставке.

5. Команды движения (move)
move — список команд, который исполняет drive():

Код	Действие
10 + n	ехать n клеток по 1-му этажу
20 + n	ехать n клеток по 2-му этажу
43	заезд на пандус
42	съезд с пандуса
44	двойной пандус (зарезервировано)
51	взять трубу с 1-го этажа
52	взять трубу с 2-го этажа
53	выгрузить трубу
60 / 61 / 62	поворот: против часовой / по часовой / на 180°
6. Направления (robot_dir)
Значение	Направление
1	вверх
2	вправо
3	вниз
4	влево
Спрайт robot.png должен изначально смотреть вверх — иначе логика поворотов разойдётся с картинкой.

7. Ключевые функции
Навигация и поиск пути
Wave(y, x) — волновой алгоритм (BFS). Заполняет матрицу wave стоимостями достижения каждой клетки из (y, x). Учитывает проходимость по dict_p и штрафы за пандусы (+2 за 61/63 по вертикали, 62/64 по горизонтали).

FindPath(y, x) — строит путь от текущей позиции до (y, x), спускаясь по wave в сторону уменьшения стоимости. Возвращает (path, tube) — путь и клетку трубы.

calc_path() — перебирает 6 перестановок объезда труб, для каждой считает суммарную длину (dlina), выбирает минимальную и сохраняет её в fin_path.

Планирование и исполнение движения
make_drive(path) — превращает путь (список координат) в список команд move. Учитывает повороты (rotate_pro) и тип клетки. Сохраняет и восстанавливает robot_dir, чтобы планирование не влияло на состояние робота. Накапливает длину маршрута в dlina.

drive(t) — исполняет команды из move. Для поворотов вызывает rotate(), для движения — robot_move(). t — задержка cv2.waitKey в мс (для наглядности 10–30).

robot_move(y, x, t) — плавно перемещает робота из текущей клетки в (y, x) с пошаговой анимацией. Накладывает спрайт на поле с учётом маски прозрачности. Координаты зажимаются в 0..7.

rotate(n) — физически поворачивает спрайт (0 — против часовой, 1 — по часовой, иначе — 180°) и обновляет robot_dir.

rotate_pro(N) — вычисляет код команды поворота (60/61/62), чтобы робот смотрел в направлении N, не меняя robot_dir. Возвращает 59, если поворот не нужен.

Отрисовка
draw_pole() — копирует pole_draw в левую часть images_array.

Wave_pole() — рисует значения wave поверх поля в правой части images_array.

show_pole() — собирает оба изображения и выводит в окно pole.

draw_robot() — накладывает спрайт робота на pole_draw в текущей позиции.

8. Как это работает по шагам
Сборка поля. Цикл по map_draw подставляет img/<код>.png в соответствующие клетки pole (80×80 пикселей на клетку).

Постановка робота. robot_pos = [4,4], draw_robot() накладывает спрайт.

Перебор маршрутов. calc_path() формирует 6 порядков объезда труб, для каждого:

от текущей позиции вызывается Wave;

FindPath строит путь до очередной трубы;

make_drive превращает путь в move и прибавляет dlina;

робот «телепортируется» в клетку трубы для следующего шага.

Выбор лучшего. Находится минимум dlini, его 4 участка сохраняются в fin_path.

Проигрывание. Для каждого участка: make_drive(fin_path[i]) → drive(1) → робот реально едет и поворачивается, robot_pos обновляется.

9. Отладка
print(move) после make_drive — посмотреть сгенерированные команды.

print(dlina) — длина текущего маршрута.

print(dlini) в calc_path — длины всех 6 вариантов.

print(fin_path) — выбранный маршрут.

print(robot_pos) после каждого drive — проверить, что робот доехал куда надо.

drive(1) → drive(30) — движение станет заметным.

Если робот «не рисуется» — убедитесь, что внутри robot_move вызывается show_pole(), а не только draw_pole() (иначе окно не перерисовывается).

10. Известные ограничения
Волновой алгоритм не учитывает текущее направление робота — маршрут может содержать лишние повороты.

calc_path перебирает только 6 перестановок из 24 (фиксирован последний пункт trubi[4]).

Команда 44 (двойной пандус) зарезервирована, но в drive не реализована.

Спрайт robot.png должен смотреть вверх (dir 1), иначе robot_dir и картинка разойдутся.

rotate_pro не меняет robot_dir — это сделано намеренно, чтобы make_drive не влиял на состояние робота. robot_dir меняется только в rotate() во время drive. Не добавляйте присваивание robot_dir в rotate_pro — вернётся проблема двойных поворотов.
