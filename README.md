# RRO2027-Future-Ingeeners-
пометки для будущего меня и санечки

Симулятор робота для категории **«Будущие инженеры»** РРО-2026, задание **«Ремонт труб»**.
Робот должен найти на поле 3 трубы, отвезти их к зелёной подставке и выложить по регламенту:
две трубы одного цвета по бокам, труба другого цвета посередине.

Всё написано на Python + OpenCV, поле рисуется в одном окне.

## Файлы

| Файл | Что это |
|---|---|
| `simulator_slam.py` | Главный симулятор: робот сам исследует поле (SLAM), собирает трубы и выкладывает их |
| `simulator_sputnik.py` | Режим «спутник»: робот видит всё поле сверху камерой над полем и сразу едет по трубам |
| `help_16.py` | Шпаргалка по OpenCV (только комментарии, ничего не запускает) |
| `img/` | Картинки клеток поля, робота и поля целиком |

## Как запустить

```bash
pip install opencv-python numpy
python simulator_slam.py
```

1. Откроется окно с полем. Нажмите любую клавишу — робот повернётся на месте и осмотрится.
2. Дальше он сам исследует поле, собирает трубы и выкладывает их на подставку.
3. После этого можно ездить с клавиатуры: стрелки — ехать и поворачивать, пробел — скан, Esc — выход.

Стартовая клетка задаётся в конце `simulator_slam.py`: `robot_pos = [y, x]`.

## Что видно в окне

```
| поле (что на самом деле) | панель | карта робота (что он узнал) |
        0..690 px          690..810       810..1490 px
```

- **Слева — поле.** Это «мир», его знает только симулятор. Зелёные квадратики вокруг робота — его датчики бортика.
- **Посередине — панель:**
  - `L F R` — датчики бортика слева, спереди, справа (красный — видит бортик);
  - `Sobrano` — какие трубы и в каком порядке собраны;
  - `Podstavka` — что лежит на зелёной подставке;
  - `V robote` — стопка труб в роботе (справа верхняя, её снимают первой);
  - буква «Т» с роботом — 4 клетки, которые камера видит перед роботом;
  - внизу — область интереса: клетка прямо перед роботом, как её видит камера.
- **Справа — карта робота 17×17.** Только то, что робот увидел сам. Робот стартует в её центре, потому что не знает, где он на поле. Красные линии — найденные края поля, зелёные точки — путь до ближайшего неизвестного места.

## Поле и коды клеток

Поле — 8×8 перекрёстков (`map_draw`), каждая клетка — это код:

| Код | Что это |
|---|---|
| `1` | нижний ярус (белый пол) |
| `2` | секция верхнего яруса (чёрная) |
| `61` `62` `63` `64` | пандусы: `61` спуск вниз, `62` влево, `63` вверх, `64` вправо |
| `121` `122` / `151` `152` | синяя / красная труба на нижнем ярусе (`…1` лежит вдоль строки, `…2` вдоль столбца) |
| `221` `222` / `251` `252` | синяя / красная труба на верхнем ярусе |
| `31` `32` `33` `34` | зелёная подставка у нижней / левой / верхней / правой границы |
| `1210` … `2520` | пустая подставка, откуда забрали трубу (код трубы + `0`) |
| `312` `315` … `345` | зелёная подставка с трубой (код подставки + цвет: `2` синяя, `5` красная) |

Правила проезда — в словарях:
- `dict_p` — куда можно ехать из клетки: вверх, вправо, вниз, влево. Например, с пола `1` нельзя сразу на секцию `2`, только через пандус.
- `dict_tube` — с какой стороны можно подъехать к трубе или подставке (к трубе — только поперёк неё).

Расстановка задаётся в `map_draw` в начале `simulator_slam.py`. По регламенту на поле 10 пандусов и 20 секций верхнего яруса, 2 трубы на нижнем ярусе и 1 на верхнем, 3 подставки в ряд у границы.

## Как работает SLAM (по шагам)

Робот не пользуется `map_draw` и `robot_pos` — это правда мира. Он знает только то, что увидел, и сколько проехал и повернулся от старта.

1. **Осмотр на месте** — `slam_step1`. Робот смотрит клетку под собой и делает 4 поворота, на каждом сканирует.
2. **Скан** — `slam_skan`:
   - камера (`camera_view`) видит 3×3 клетки перед роботом;
   - `scan_ahead_4` распознаёт 4 клетки буквой «Т» (`detect_cell` по цветам) и записывает коды в `slam_map`;
   - датчики `red_sensors` ищут красный бортик слева, спереди, справа;
   - клетки за бортиком не считываются, чтобы не распознать их неправильно.
3. **Края поля** — `obnovit_granitsy`. Увидел бортик сверху — знаю верхний край, а раз поле 8×8, то и нижний.
4. **Куда ехать** — `plan_issledovaniya`. Поиск в ширину по парам «клетка + направление»: шаг и поворот стоят одинаково. Цель — ближайшее место, откуда камера увидит неизвестную клетку.
5. **Главный цикл** — `slam_explore`. Одно действие (шаг или поворот) → скан → новый план. На пандусе робот не останавливается, не поворачивает и не сканирует, а медленно проезжает его целиком.
6. **Когда хватит** — `vse_naideno`. Края поля известны, найдены 3 трубы и подставка, и до всех можно доехать.
7. **Задание** — `slam_zadanie`:
   - `vyrezat_8x8` вырезает из карты робота поле 8×8;
   - `calc_path` выбирает самый короткий порядок объезда труб;
   - робот забирает трубы (`zabrat_trubu`): на их месте остаются пустые подставки;
   - `vygruzit_truby` выкладывает трубы. Они лежат в роботе стопкой, поэтому первой снимается последняя собранная, и каждая едет на своё место по регламенту (`poryadok_vygruzki`).

## Главные функции `simulator_slam.py`

| Функция | Что делает |
|---|---|
| `rotate`, `robot_move` | повернуть робота / проехать с анимацией |
| `Wave`, `FindPath`, `make_drive`, `drive`, `calc_path` | волновой алгоритм, путь до трубы, команды движения, маршрут по всем трубам |
| `camera_view` | камера робота: 3×3 клетки перед ним, «вперёд» всегда вверх |
| `detect_cell`, `find_col` | распознать клетку по цветам (HSV-маски) |
| `scan_ahead_4`, `skan_pod_soboi` | скан «Т» перед роботом / клетки под ним |
| `red_sensors`, `draw_sensors` | 3 датчика бортика и телеметрия `L F R` |
| `slam_step1`, `slam_explore`, `slam_zadanie` | осмотр, исследование, выполнение задания |
| `plan_issledovaniya`, `vse_naideno` | планировщик исследования и условие остановки |
| `zabrat_trubu`, `vygruzit_truby`, `poryadok_vygruzki` | подбор и выгрузка труб |
| `draw_slam_map`, `draw_scan_panel`, `draw_metrika` | вторая карта, панель скана, метрика |
| `key_drive` | ручное управление с клавиатуры |
